# SSH Manager TUI

Терминальный менеджер SSH-сессий на Go со вкладками, SFTP и пробросом портов.
После установки запускается короткой командой `sshm`.
После подключения открывается интерактивная SSH-консоль, а SFTP-панель можно
показать слева клавишами `Ctrl+B`.

## Возможности

- сохранение профилей в `~/.ssh-manager-tui.json` (`0600`);
- переиспользуемые профили пользователя с логином, паролем или приватным
  ключом: один профиль можно назначить нескольким хостам;
- автоимпорт подключений из history Bash, Zsh и Fish с выбором хостов,
  профилей пользователя и групп перед сохранением;
- парольная авторизация и ключи `id_ed25519`, `id_ecdsa`, `id_rsa`;
- отдельная проверка авторизации публичным ключом перед сохранением;
- интерактивный SSH PTY с синхронизацией размера окна;
- ANSI/VT-рендеринг с 16/256 цветами, truecolor, alternate screen и DEC-графикой
  для цветных prompt-тем и полноэкранных приложений вроде `htop`;
- лениво загружаемое дерево удалённых файлов;
- рекурсивное скачивание и загрузка файлов/каталогов с процентом, скоростью и
  именем текущего файла; после завершения прогресс скрывается, а результат
  остаётся в строке статуса;
- загрузка перетащенных из проводника файлов и каталогов в текущий каталог
  терминала либо в выбранный каталог SFTP;
- независимые SSH-сессии во вкладках;
- четыре сохраняемые тёмные темы: Midnight, Deep Ocean, оливково-оранжевая
  Steam Source в стиле интерфейсов Valve эпохи Counter-Strike: Source и
  Windows 98 Dark с классическим сегментированным progress bar;
- группы хостов и сортировка по числу успешных подключений внутри группы;
- Local (`-L`), Remote (`-R`) и Dynamic SOCKS5 (`-D`) пробросы портов с
  ручным запуском или автозапуском при подключении;
- проверка host key: известные ключи читаются из `~/.ssh/known_hosts`, а новый
  или изменившийся ключ показывается вместе с SHA256-отпечатком и сохраняется в
  `~/.ssh-manager-tui_known_hosts` только после явного подтверждения.

## Установка

Готовые релизы не требуют Go и сами выбирают архитектуру `amd64` или `arm64`.
Установщик проверяет SHA-256 скачанного файла и добавляет каталог приложения в
`PATH` автоматически.

### Linux

```bash
curl -fsSL https://raw.githubusercontent.com/savuerka/ssh-manager-tui/main/scripts/install-linux.sh | sh && exec "$SHELL" -i
sshm
```

Если `/usr/local/bin` уже находится в `PATH`, установщик использует его и при
необходимости запросит `sudo`. Иначе приложение устанавливается в
`~/.local/bin`, а `PATH` записывается в конфигурацию текущей оболочки. Последняя
часть команды перезапускает оболочку, поэтому `sshm` доступен сразу.

### macOS

```bash
curl -fsSL https://raw.githubusercontent.com/savuerka/ssh-manager-tui/main/scripts/install-macos.sh | sh && exec "$SHELL" -i
sshm
```

Поддерживаются Mac на Intel и Apple Silicon. Правила выбора каталога и
настройки `PATH` те же, что на Linux.

### Windows

Откройте PowerShell и выполните:

```powershell
irm https://raw.githubusercontent.com/savuerka/ssh-manager-tui/main/scripts/install-windows.ps1 | iex
sshm
```

Приложение устанавливается в `%LOCALAPPDATA%\Programs\sshm`. Установщик
добавляет этот каталог и в пользовательский `PATH`, и в текущую сессию
PowerShell, поэтому перезапуск терминала не требуется. Также создаётся
совместимая команда `ssh-manager`.

Для установки конкретной версии вместо последней задайте `SSHM_VERSION`,
например `SSHM_VERSION=v1.2.3` на Linux/macOS или
`$env:SSHM_VERSION = "v1.2.3"` в PowerShell. Каталог можно переопределить через
`SSHM_INSTALL_DIR`.

### Сборка из исходников

Для этого варианта нужны Go 1.25 или новее, `make` и клонированный репозиторий:

```bash
make test
sudo make install PREFIX=/usr/local
```

Одновременно создаётся совместимый симлинк `ssh-manager`, поэтому старое имя
продолжит работать. Удаление выполняется с тем же префиксом:

```bash
make uninstall
# или: sudo make uninstall PREFIX=/usr/local
```

Для сборки без установки:

```bash
make build
./sshm
```

## Обновление

У установленного релиза:

```bash
sshm update --check
sshm update
```

Команда получает manifest последнего релиза, выбирает артефакт под текущие
`linux/darwin` и `amd64/arm64`, проверяет размер и SHA-256, записывает файл рядом
с текущим бинарником и атомарно заменяет его. Если `sshm` установлен системно и
текущий пользователь не может заменить `/usr/local/bin/sshm`, обновление нужно
выполнить повторным запуском установщика. В Windows для обновления также
повторно запустите PowerShell-команду установки после закрытия `sshm.exe`.

По умолчанию используется manifest последнего GitHub Release. Его можно
переопределить при сборке (`make install UPDATE_URL=https://…/manifest.json`)
или во время запуска (`SSHM_UPDATE_URL=https://…/manifest.json sshm update`).
Updater принимает удалённые manifest и артефакты только по HTTPS; HTTP разрешён
лишь для localhost в тестовых окружениях.

Если приложение обновляется непосредственно из клонированного репозитория:

```bash
make update
```

Эта цель выполняет только fast-forward `git pull`, запускает тесты и повторяет
установку с текущим `PREFIX`, поэтому локальные изменения не перезаписываются.

Версия и commit установленной сборки доступны через `sshm version`.

### Подготовка релиза

Обычные push и pull request проверяются workflow `.github/workflows/ci.yml`:
тестами, `go vet` и сборкой для Linux, macOS и Windows на `amd64`/`arm64`.

Публикация полностью автоматическая. Создайте и отправьте SemVer-тег:

```bash
git tag v1.0.0
git push origin v1.0.0
```

Workflow `.github/workflows/release.yml` ещё раз запускает тесты, собирает шесть
бинарников, создаёт `manifest.json` и `checksums.txt`, а затем публикует GitHub
Release с автоматически сформированным описанием. Теги с суффиксом, например
`v1.1.0-rc.1`, публикуются как pre-release и не заменяют последнюю стабильную
версию.

Тот же набор файлов можно собрать локально:

```bash
make release VERSION=v1.0.0 GITHUB_REPOSITORY=savuerka/ssh-manager-tui
```

## Клавиши

Управление вкладками доступно на любом экране:

- `Ctrl+T` открывает новую вкладку с окном выбора хоста;
- `Ctrl+W` закрывает текущую вкладку и её SSH-соединение;
- `Alt+←/→` на Linux или `Ctrl+Shift+←/→` на macOS переключает вкладки по кругу;
- `Alt+1…9` на Linux или `Ctrl+Shift+1…9` на macOS сразу открывает вкладку с указанным номером;
- `Ctrl+B` показывает или скрывает SFTP-панель подключённой вкладки;
- `Alt+P` на Linux или `Ctrl+Shift+P` на macOS открывает менеджер проброса портов.

Если комбинации различаются, сначала указана клавиша Linux, затем macOS. Сам интерфейс
определяет платформу при сборке и показывает только подходящий вариант. На macOS
системные `Control+←/→`, `Control+Space` и клавиша `Option` не перехватываются:
альтернативные действия используют `Ctrl+Shift`. Для
буквенных сочетаний используется физическая клавиша, поэтому они работают и
при включённой нелатинской раскладке в терминалах с Kitty keyboard protocol.

В списке сессий: `↑/↓` — выбор, `Enter` — подключиться, `n` — новый хост,
`e` — изменить выбранный хост,
`p` — менеджер профилей пользователя, `i` — автоимпорт из shell-history,
`g` — выбрать или ввести группу для выбранного хоста: список фильтруется по
введённому фрагменту, `↑/↓` выбирают подсказку, а `Tab` подставляет её (пустая
строка убирает из группы),
`t` — переключить и сразу сохранить тему, `d` — удалить хост. `q` закрывает текущую вкладку, если есть другие, и
завершает приложение, если вкладка последняя.

В менеджере профилей пользователя (`p`) клавиша `n` создаёт профиль, а
`Enter`/`e` изменяет выбранный. Профиль содержит название, логин и, при
необходимости, пароль либо путь к приватному ключу. При переименовании профиля
ссылки на него во всех хостах обновляются автоматически. Удалить профиль,
который используется хостом, нельзя.

В форме нового хоста поле «Профиль» переключается клавишами `←/→`. Пустое
значение означает ручной ввод логина, пароля и ключа; выбранный профиль хранится
как ссылка, поэтому его последующие изменения применяются ко всем связанным
хостам.

Мастер автоимпорта (`i`) читает `HISTFILE`, `~/.bash_history`,
`~/.zsh_history` и `~/.local/share/fish/fish_history`, не выполняя найденные
команды. `Space` отмечает хост, `a` отмечает все, `p` или `←/→` назначают
профиль, `g` задаёт группу, а `f` либо кнопка «Завершено» сохраняет выбор.
Распознаются в том числе `ssh -p`, `ssh -l`, `ssh -i` и адреса `ssh://`.

После подключения:

- SFTP-панель по умолчанию скрыта; `Ctrl+B` показывает её;
- `Ctrl+Space` на Linux или `Ctrl+Shift+Space` на macOS переключает фокус между показанной SFTP-панелью и консолью;
- при открытии SFTP через `Ctrl+B` фокус сразу переходит в панель, а при
  скрытии возвращается в SSH-консоль;
- клик по SFTP-панели или SSH-консоли переключает фокус; вкладки и показанные
  в интерфейсе подсказки клавиш также можно нажимать мышью;
- `↑/↓` выбирают узел дерева, `Enter` или `→` раскрывает каталог, `←` сворачивает;
- дерево стартует в домашнем каталоге пользователя, но `Backspace` поднимает
  корень дерева на уровень выше, `/` сразу открывает корень файловой системы,
  а `Home` возвращает в домашний каталог;
- содержимое автоматически перечитывается при сворачивании и раскрытии;
  `r` или `F5` принудительно обновляет выбранный каталог;
- `n` создаёт каталог внутри выбранного каталога (или рядом с выбранным файлом);
  `c` копирует, `m` перемещает выбранный объект в указанный удалённый каталог;
  `d` или `Delete` удаляет выбранный файл или каталог после подтверждения, включая
  содержимое непустого каталога;
- `Ctrl+D` открывает локальный диалог, где `s` сохраняет выбранный
  удалённый файл/каталог в текущий локальный каталог;
- `Ctrl+U` открывает локальный диалог для загрузки файла или каталога в
  выбранный удалённый каталог; `Space` отмечает несколько объектов, а `u`
  запускает загрузку (`Enter` сразу загружает выбранный файл);
- протягивание левой кнопкой мыши выделяет и подсвечивает текст SSH-консоли;
  сразу после отпускания кнопки выделенный текст автоматически копируется в
  системный буфер обмена;
- колесо мыши над SSH-консолью прокручивает историю вывода до 10 000 строк;
  ввод с клавиатуры или вставка возвращает отображение к последней строке;
- `Shift+Insert` или клик правой кнопкой мыши по SSH-консоли вставляет
  содержимое системного буфера;
- `Ctrl+X` отменяет активное скачивание или загрузку; незавершённый временный
  файл удаляется;
- файл или каталог, перетащенный из графического проводника на SSH-консоль,
  загружается в текущий удалённый каталог. Каталог отслеживается по стандартному
  сообщению shell `OSC 7`; если shell его не отправляет, используется домашний
  каталог подключения. При перетаскивании над SFTP загрузка идёт в выбранный
  каталог, а если выбран файл — в содержащий его каталог;
- при потере сети или зависании SSH окно переподключения автоматически повторяет
  попытки без ограничения их числа; `Enter` запускает попытку немедленно, а
  `Esc` или кликабельная «Отмена» прекращает цикл и возвращает к списку сессий;
- `Esc`, затем `q` (в течение 700 мс) отключается и возвращает к списку сессий;
- `Ctrl+Q` завершает программу.

В менеджере проброса портов (`Alt+P` на Linux, `Ctrl+Shift+P` на macOS):

- `n` создаёт новый туннель, `e` изменяет, `d` удаляет;
- `Enter` или `Space` запускает либо останавливает выбранный туннель;
- при редактировании `←/→` выбирают Local, Remote или SOCKS5 и переключают
  автозапуск;
- `Esc` возвращает к списку туннелей, а затем закрывает окно.

Local-туннель слушает порт на локальном компьютере и открывает целевой адрес
через SSH. Remote-туннель слушает порт на SSH-сервере и направляет его к
локальному адресу. Dynamic-туннель запускает локальный SOCKS5-прокси, причём
имена хостов разрешаются на стороне SSH-сервера.

`Ctrl+D`/`Ctrl+U` управляют передачей только при фокусе на
SFTP-панели. При
фокусе на SSH-консоли они передаются удалённой оболочке как обычные управляющие
клавиши (EOF и очистка строки соответственно).

`Ctrl+Space` на Linux работает и в терминалах с расширенным клавиатурным
протоколом, и в старом режиме, где эта комбинация кодируется как `Ctrl+@`.
На macOS используется `Ctrl+Shift+Space`, чтобы не пересекаться с системным
переключением источника ввода на `Control+Space`.
